# 待开发功能文档

## 文档定位

本文档维护 V2 之后的功能候选池。任何新业务能力都先进入这里评估，不直接进入 V2 稳定化范围。

优先级说明：

- `P0`：会显著影响当前主链路质量，但仍需确认是否属于缺陷修复或新功能。
- `P1`：下一大版本优先候选。
- `P2`：有价值但依赖更多场景或架构准备。
- `Hold`：明确不进入近期版本。

主体路线只记录方向和版本边界，具体待办和候选能力维护在本文档。模块级细节维护在 `docs/modules/`。

## P0：质量增强候选

### 简历解析 vNext 后续

当前状态：

- vNext 已有 section prompts、parse run、blocks、field candidates、source text。
- 候选人详情页和修正页已接入证据闭环。
- `resume-parser-vnext-0.3` 已修复 work/project/self-evaluation section 边界问题。

下一步候选：

- basics fallback：支持无 `姓名` 标签、导出型 PDF、文件名不可用时的姓名识别。
- education recovery：支持无标题教育经历中学校、学历、专业、时间的恢复。
- item-level evidence：工作职责和项目条目拆成更短 source text。
- low-confidence policy：区分必填核心字段和可选增强字段，避免证书等可选项过度影响质量。
- correction feedback：把人工修正来源转为后续 parser 回归样本。

归属：

- 属于解析质量增强实验。
- 不新增业务入口。
- 不改 V2 主流程。

### 匹配解释质量

当前状态：

- 已有本地兜底分维度评分。
- 已能输出 matched points / weak points。

候选能力：

- 更严格的 AI JSON 分项解释。
- 解释内容结构化校验和兜底。
- 证据片段与维度评分一致性校验。
- 对低置信字段参与评分时给出更明确的复核提示。

## P1：下一大版本候选

### 推荐报告历史保存

当前状态：

- 推荐摘要可生成、编辑、复制、下载 Markdown，但不入库。

建议范围：

- 新增推荐报告历史表。
- 保存 Markdown 草稿。
- 支持历史报告列表。
- 支持打开历史报告继续编辑、复制、下载。
- 保存或更新报告时写入时间线。

### 文本粘贴录入简历

当前状态：

- 只支持文件上传。

建议范围：

- 新增文本录入入口。
- 录入时选择岗位。
- 复用现有解析、评分、重复识别、时间线和上传任务状态链路。
- 明确文本录入生成的 `ResumeFile` 或等价记录如何保存。

### ZIP 批量上传

当前状态：

- 前端可多文件选择并逐个上传，不支持 ZIP 解包。

建议范围：

- 上传 ZIP。
- 服务端解包。
- 逐个文件复用现有单文件处理链路。
- 每个文件保留独立任务状态和失败原因。

### PDF / Word 推荐报告导出

当前状态：

- 仅支持 Markdown 下载。

建议范围：

- 从已保存报告导出 PDF / Word。
- 导出前仍允许人工编辑。
- 导出内容继续遵守敏感信息和风险提示约束。

### 上传处理异步化

当前状态：

- 同步处理为主，已记录任务状态。

触发条件：

- 真实批量上传等待时间明显影响使用。

建议范围：

- 引入后台队列。
- 保留现有任务状态表作为前端查询基础。
- 不改变上传任务和候选人生成的业务语义。

## P2：人才库和协作增强

### 候选人主档案

候选能力：

- 候选人主档案合并。
- 多岗位归属模型。
- 重复候选人自动合并或建议合并。
- 历史投递、沟通、评价沉淀。

当前判断：

- 这会改变核心数据模型，不进入 V2。
- 需要和人才库大版本一起设计。

### 完整招聘协作

候选能力：

- 多角色权限。
- 审批流。
- 面试日程。
- 邮件、短信、企业微信、飞书通知。
- ATS 对接。
- Offer 管理。
- 招聘数据大屏。

当前判断：

- 当前项目定位仍是简历初筛工作台，不做完整 ATS。

## Hold：明确不进入当前阶段

- 图片简历 OCR。
- 完整 CRM 式人才库运营。
- 自动合并重复候选人。
- 新后台任务架构直接回流 V2。
- 多岗位同时归属同一份简历直接回流 V2。
- 复杂权限、审批、面试日程、通知、ATS、Offer、招聘大屏直接回流 V2。

## 维护规则

- 新业务能力先进入本文档，不直接进入 ROADMAP 或模块实施计划。
- 进入开发前，需要明确归属模块、范围边界、验收方式和是否影响 V2 冻结规则。
- 已完成或废弃的 backlog 项需要在对应条目下记录结论，不直接删除历史。
