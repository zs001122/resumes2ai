# 主体开发路线

## 1. 项目定位

AI 简历筛选工作台面向 HR 和招聘负责人，目标是把岗位驱动的简历初筛流程做成可试用、可复核、可迭代的工作台。

当前产品不追求完整 ATS，也不覆盖招聘全流程。主目标是：

- 帮 HR 基于岗位快速收集、解析和初筛简历。
- 让解析和评分过程可解释、可复核、可人工修正。
- 把候选人、岗位、匹配结果、复核动作和推荐摘要沉淀成可追溯记录。
- 在不扩大 V2 业务范围的前提下，持续提升简历解析、匹配和证据体验质量。

## 2. 总体产品方向

长期方向分为三层：

1. 招聘初筛主链路：岗位、上传、解析、评分、候选人复核、人才库、推荐摘要。
2. 解析和匹配智能层：简历结构化、证据候选、低置信提示、匹配解释、人工修正反馈。
3. 工程和验收体系：自动化测试、真实样本回归、演示数据、文档记录、稳定启动部署。

当前阶段优先级：

- 第一优先级：V2 主链路稳定、可启动、可验收、可演示。
- 第二优先级：vNext parser 证据闭环，提高解析质量和人工修正效率。
- 第三优先级：下一大版本候选能力评估，不回流 V2。

## 3. 当前主线版本状态

当前主线版本为 V2 稳定化阶段，功能截止在 V2.1.2 能力范围。

已形成闭环：

```text
工作台总览
  -> 创建 / 管理岗位
  -> 岗位内上传或统一上传简历
  -> 查看上传队列与失败重试
  -> 解析简历并生成候选人
  -> 自动评分与分项解释
  -> 候选人列表筛选与批量操作
  -> 候选人详情复核、原文证据、备注、时间线
  -> 人才库沉淀与跨岗位搜索
  -> 岗位标准版本变更与历史候选人重评
  -> 重复候选人人工复核
  -> 推荐摘要 Markdown 生成、编辑、复制、下载
```

当前实验分支重点：

- 分支：`experiment/resume-parse-vnext`
- 方向：简历解析 vNext 证据闭环。
- 边界：不新增业务入口，不改 V2 上传后主流程。
- 当前版本：`resume-parser-vnext-0.3`。

## 4. 模块地图

### 4.1 前端

职责：

- 工作台总览、岗位列表、岗位详情、上传队列。
- 候选人列表、候选人详情、解析修正页、原文高亮。
- 人才库、重复复核、推荐摘要 Markdown 编辑和下载。
- vNext parse run 证据展示、field candidates 选择、低置信字段提示。

维护文档：[modules/frontend.md](./modules/frontend.md)

### 4.2 后端

职责：

- FastAPI 接口、SQLite 数据模型、Repository、迁移。
- 岗位、上传、简历文件、候选人、匹配结果、时间线、备注、标签、人才库。
- 重试、重复候选人识别、岗位标准版本、重评和推荐摘要接口。
- parse run、blocks、field candidates 等 vNext 解析证据数据。

维护文档：[modules/backend.md](./modules/backend.md)

### 4.3 解析算法

职责：

- 文件文本提取。
- 规则优先的简历结构化解析。
- AI 兜底增强。
- section boundary、field candidates、source text、confidence、rejection reason。
- 真实样本 fixtures 和 parser 回归。

维护文档：[modules/parser.md](./modules/parser.md)

### 4.4 匹配评分

职责：

- 岗位标准和候选人字段的匹配评分。
- 必备技能、相关技能、项目证据、经验、学历、城市、排除项风险等维度。
- matched points / weak points。
- 推荐摘要 Markdown 和敏感信息约束。

维护文档：[modules/matching.md](./modules/matching.md)

### 4.5 数据与测试

职责：

- 后端 pytest、前端 lint/build、API 手动验收脚本。
- 真实样本诊断脚本、fixtures、E2E 记录。
- 演示数据清理和主流程回归。

维护文档：[modules/testing.md](./modules/testing.md)

### 4.6 工程运维

职责：

- 本地环境、启动脚本、端口、环境变量、SQLite、uploads。
- Git 分支、GitHub 凭据、部署和开发机运行状态。
- 服务故障排查和开发流程约束。

维护文档：[modules/operations.md](./modules/operations.md)

## 5. 版本路线

### 5.1 MVP：已完成

目标：跑通最小招聘初筛流程。

完成内容：

- 创建岗位。
- 上传简历。
- 解析基础结构化字段。
- 生成匹配结果。
- 候选人状态流转。
- MVP API 和基础 UI 验收。

当前状态：历史阶段，不再单独维护任务拆解文档。关键结论沉淀在本路线和模块文档。

### 5.2 V2：已完成

目标：从 MVP 扩展为可试用招聘工作台。

完成内容：

- 工作台首页和待办异常概览。
- 上传队列和失败重试。
- 候选人列表筛选、批量操作。
- 候选人详情、匹配解释、原文复核、备注、时间线。
- 轻量人才库、标签、历史岗位和跨岗位搜索。
- 岗位复制、暂停、重开、关闭和 JD 质量检查。

当前状态：已完成，进入稳定化。

### 5.3 V2.1 / V2.1.1 / V2.1.2：已完成

目标：补齐 V2 主链路缺口。

完成内容：

- 统一上传入口和岗位内上传复用同一处理链路。
- 疑似重复候选人识别。
- 岗位标准版本和历史候选人重评。
- 推荐摘要 Markdown 生成、编辑、复制和下载。
- 重复候选人人工复核。
- 岗位上下文边界修复，避免跨岗位误操作。

当前状态：V2 功能截止版本。

### 5.4 V2 稳定化：当前主线

目标：让当前能力稳定、可验收、可演示、可维护。

允许事项：

- bug 修复。
- 验收脚本补齐。
- 文档、部署、演示数据和启动说明补齐。
- 不改变产品范围的小 UI 文案、状态展示和错误提示修正。
- 数据迁移一致性和本地开发体验修正。
- 影响现有主链路质量的解析、匹配和证据解释缺陷修复。

禁止事项：

- 新业务能力。
- 新数据模型。
- 新上传形态。
- 新导出形态。
- 新后台任务架构。
- 候选人主档案合并、自动合并、多岗位归属。

### 5.5 vNext parser 实验：当前重点

目标：不改 V2 主流程的前提下，提升简历解析质量和人工修正效率。

已经完成：

- vNext section prompt 模板。
- section parser、parse run、blocks、field candidates。
- 候选字段携带 `extractor`、`confidence`、`source_text`、`rejection_reason`。
- 候选人详情页展示解析证据。
- 修正页展示候选字段，低置信字段优先，点击候选值可填入表单。
- `resume-parser-vnext-0.3` 修复 work/project/self-evaluation section 边界。

下一阶段：

- basics fallback：无标签姓名识别。
- education recovery：无标题教育恢复。
- item-level evidence：缩短工作和项目 source text。
- confidence policy：核心字段和可选字段分层。
- correction feedback：人工修正反馈沉淀为 parser regression fixture。

### 5.6 下一大版本候选

新业务能力统一进入 [BACKLOG.md](./BACKLOG.md)，当前候选包括：

- 推荐报告历史保存。
- 文本粘贴录入简历。
- ZIP 批量上传。
- PDF / Word 推荐报告导出。
- 上传处理异步化。
- 候选人主档案和多岗位归属。
- 完整招聘协作、通知和 ATS 对接。

## 6. 当前冻结规则

V2 冻结后只允许：

- 阻断验收的 bug 修复。
- 验收脚本、清理脚本和文档补齐。
- 启动、迁移、演示数据和本地开发体验修正。
- 不改变业务范围的小 UI 文案、状态展示和错误提示修正。
- 解析、匹配、证据解释等现有主链路质量修复。

V2 冻结后禁止：

- 新业务功能。
- 新数据模型。
- 新上传入口或上传形态。
- 新导出形态。
- 新后台任务架构。
- 候选人主档案合并、自动合并、多岗位归属。

- `README.md`：项目入口，只维护启动、验收和文档入口。
- `ROADMAP.md`：主体路线，只有产品方向、版本边界、模块划分或阶段目标变化时更新。

- `BACKLOG.md`：待开发功能池，新增能力先进入这里。
- `docs/modules/*.md`：模块级计划、状态、缺陷和验收规则，各模块自行维护。
