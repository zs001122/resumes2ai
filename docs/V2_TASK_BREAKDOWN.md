# AI 简历筛选工作台 V2 开发任务拆解

## 1. 文档定位

本文档用于将 V2 设计方案拆解为可开发、可验收的工程任务清单。

上位文档：

- [HR_RESUME_SCREENING_TOOL_DESIGN.md](./HR_RESUME_SCREENING_TOOL_DESIGN.md)
- [HR_RESUME_SCREENING_TOOL_V2_DESIGN.md](./HR_RESUME_SCREENING_TOOL_V2_DESIGN.md)
- [MVP_TASK_BREAKDOWN.md](./MVP_TASK_BREAKDOWN.md)
- [TECH_STACK_DECISION.md](./TECH_STACK_DECISION.md)

执行原则：

- V2 继续遵循岗位驱动流程，不改变 MVP 已完成的主闭环。
- V2 目标是从“可演示闭环”升级为“可试用招聘工作台”。
- AI 仍然只做辅助判断，所有推荐、风险和评分必须可解释、可复核。
- 轻量人才库只做候选人沉淀和跨岗位搜索，不扩展为完整 CRM。
- 如开发中需要改变整体流程、模块边界或合规边界，必须先确认是否同步修改设计文档。

## 2. V2 开发目标

V2 需要在 MVP 基础上完成以下增强闭环：

```text
进入工作台首页
  -> 查看待处理事项和异常
  -> 批量上传简历
  -> 查看上传、解析、评分状态
  -> 处理失败和低置信度候选人
  -> 在候选人列表中组合筛选和批量操作
  -> 在详情页复核 AI 分项解释和原文证据
  -> 记录备注、时间线和状态变化
  -> 将合适候选人沉淀到轻量人才库
```

### 3.5 Phase 11：AI 分项解释增强

#### 目标

让匹配结果从单一总分升级为可复核的分项解释和原文证据。

#### 后端任务

- 扩展 AI 匹配输出 Schema。
- 支持分项评分：必备条件、核心技能、项目经验、行业经验、工作年限、学历、加分项、风险扣分。
- 支持每个分项保存结论。
- 支持每个分项保存 evidence_text。
- 支持每个分项保存 confidence。
- 保存评分生成时间。
- 关联岗位标准版本字段，第一批可为空或使用当前岗位标准。
- AI 输出结构化校验失败时记录错误。
- 保留本地规则兜底。

#### 前端任务

- 候选人详情页展示分项评分。
- 候选人详情页展示匹配点、不匹配点、风险点和待确认项。
- 候选人详情页展示证据片段。
- 重新评分后刷新分项解释。
- 风险点使用“待确认”或“建议复核”语气。

#### 状态

已完成第一版。当前已新增匹配分项解释生成服务和 `/match/explanations` 接口，新评分、上传自动评分、批量重新评分都会保存分项解释；候选人详情页已展示分项评分、结论和证据片段。第一版分项解释基于当前结构化匹配结果和候选人字段生成，后续可升级为更强的 AI JSON 输出。后端 `compileall`、`ruff check`、前端 `npm run build` 均已通过，分项解释接口已通过 FastAPI TestClient 验证。

#### 验收

- [x] 每个匹配结果可以展示分项评分。
- [x] 每个关键结论有解释或证据说明。
- [x] AI 结构化输出失败时可恢复。
- [x] 敏感信息不参与自动评分和推荐。

## 6. 开发注意事项

- 优先复用 MVP 现有 API、Service、Repository 和数据模型边界。
- 批量上传第一阶段可以继续同步处理，但必须记录每份文件状态。
- 原文定位第一阶段基于抽取文本和片段匹配，不做 PDF 精确坐标。
- 人才库第一阶段只做轻量候选人沉淀，不引入复杂归属、权限和触达能力。
- 所有 AI 输出必须做结构化校验。
- 所有风险提示都应使用“待确认”或“建议复核”语气。
- 所有关键人工操作都应写入时间线。
- 新增能力必须保证 MVP 主流程可继续通过。
