# 前端模块文档

## 模块定位

前端负责 HR 可操作的工作台体验，包括岗位、上传、候选人、解析修正、证据复核、人才库、重复复核和推荐摘要。

当前原则：

- 不新增 V2 业务入口。
- 优先保证主链路可用、信息密度合理、证据复核高效。
- UI 优化要围绕实际操作效率，不做营销式页面。

## 当前能力

- `/dashboard` 工作台总览、待办、异常和最近活动。
- 岗位列表、岗位详情、创建、复制、暂停、重开、关闭。
- 岗位内上传和统一上传页面。
- 上传队列、失败原因、重试入口、重复风险统计。
- 候选人列表筛选、批量状态、批量入库、批量重评。
- 候选人详情：匹配解释、证据片段、原文预览、高亮、备注、时间线。
- 人才库列表、跨岗位搜索、标签管理。
- 重复候选人风险展示和人工复核操作。
- 推荐摘要 Markdown 生成、编辑、复制、下载。
- 修正页接入 vNext field candidates，支持低置信优先、候选值套用和 source text 展示。
- 修正页保存时可保留字段值来自 vNext candidate 的操作痕迹，修改记录展示“来自 vNext 候选”。
- 企业 ATS 风格第一版已覆盖首页、工作台、岗位列表和候选人修正页。

## 当前重点

### vNext 证据复核体验

已完成：

- 修正页拉取最新 parse run。
- 字段旁展示候选值。
- 低置信字段优先展示。
- 点击候选值填入表单。
- 手工编辑字段时清除 vNext 来源，避免误标。
- 保存后修改记录展示“来自 vNext 候选”。
- 候选证据支持展开/收起、复制和定位。
- extractor 和 rejection_reason 会转成更容易理解的展示文案。
- 没有 parse run 时降级为旧体验。

待优化：

- 点击 source text 后更稳定地定位和高亮原文，特别是 PDF 抽文本空白不一致时。
- 低置信字段汇总从字段名进一步转成 HR 可读复核建议。
- 在候选人详情页和修正页之间保持证据口径一致。

### UI 稳定性

已知关注点：

- Next dev server 端口 3010 曾出现进程监听但请求无响应，需要运维文档记录重启办法。
- 不跑 `next build` 时需要说明原因，避免影响当前 dev server 静态资源排查。
- 页面文本需要适配窄屏，不应和按钮、表单、证据区重叠。

## 验收

常规命令：

```powershell
cd frontend
npm run lint
npm run build
```

开发期间如不能跑 build，至少验证：

- 目标页面返回 200。
- 控制台无关键静态资源 404。
- 修正页无 parse run 时降级正常。
- 有 parse run 时低置信候选、候选值套用、source text 展示正常。

## 维护规则

- 页面级交互和 UI 调整记录在本文档。
- 涉及业务范围变化时先更新 `ROADMAP.md` 或 `BACKLOG.md`。
- 涉及 parser evidence 字段变化时同步更新 `parser.md`。
