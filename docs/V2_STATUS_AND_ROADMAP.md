## 2. 当前结论

V2 到 V2.1.2 已经形成“可试用招聘工作台”的主闭环：

```text
工作台总览
  -> 创建 / 管理岗位
  -> 上传简历
  -> 查看上传队列与失败重试
  -> 解析简历并生成候选人
  -> 自动评分与分项解释
  -> 候选人列表筛选与批量操作
  -> 候选人详情复核、备注、时间线
  -> 人才库沉淀与跨岗位搜索
  -> 岗位标准版本变更与历史候选人重评
  -> 重复候选人人工复核
  -> 推荐摘要 Markdown 生成、编辑、复制、下载
```

V2.1.2 是 V2 功能截止版本。V2 后续不再新增 V2.1.x 功能版本，只进入稳定化、验收和交付阶段。

V2 冻结后的允许事项：

- bug 修复。
- 验收脚本补齐。
- 文档、部署、演示数据和启动说明补齐。
- 不改变产品范围的小 UI 文案、状态展示和错误提示修正。
- 数据迁移一致性和本地开发体验修正。

V2 冻结后的禁止事项：

- 新业务能力。
- 新数据模型。
- 新上传形态。
- 新导出形态。
- 新后台任务架构。
- 候选人主档案合并、自动合并、多岗位归属。

## 2.1 V2 交付闭环清单

V2 稳定化阶段只围绕交付闭环展开：

- 跑通自动验收：后端测试、后端 lint、前端 lint、前端构建。
- 跑通手动验收：按 [V2_ACCEPTANCE_GUIDE.md](./V2_ACCEPTANCE_GUIDE.md) 覆盖工作台、岗位、上传、候选人、人才库、重评和重复复核。
- 准备演示数据：保留可复现的岗位和简历样例，必要时用清理脚本重置本地环境。
- 补齐启动说明：确保 README 和验收说明能让新开发者启动前后端。
- 标记已知限制：把未进入 V2 的功能统一放入下一大版本候选池。
- 修复阻断缺陷：只处理影响验收和交付的 bug。
- 冻结范围：任何新能力都必须先进入下一大版本规划，不直接进入 V2。

具体交付步骤见 [V2_RELEASE_CHECKLIST.md](./V2_RELEASE_CHECKLIST.md)。

## 3. 已完成范围

### 3.1 V2 基础能力

- V2 基础模型、Schema、Repository 和迁移。
- 上传处理任务、匹配分项解释、候选人备注、时间线、标签和标签关联。
- 候选人岗位状态与人才库状态分离。
- 操作时间线追加写入，不覆盖历史。

### 3.2 工作台首页

- `/dashboard` 页面。
- `/api/dashboard`、summary、todos、recent activities。
- 开放岗位、候选人、高匹配、待沟通、解析失败、评分失败、重复待复核等统计。
- 今日待办、异常概览、最近活动。

### 3.3 上传队列与失败重试

- 岗位内简历上传。
- 上传任务列表。
- 单任务重试和批量重试失败项。
- 上传、解析、评分状态与失败原因展示。
- 重复风险统计展示。

### 3.4 候选人列表增强

- 按状态、推荐等级、分数区间、城市、工作年限、学历、技能、风险、低置信度、入库状态筛选。
- 批量状态更新。
- 批量加入人才库。
- 批量重新评分。
- 部分候选人不属于当前岗位时跳过或返回部分失败。

### 3.5 AI 匹配解释与原文复核

- 候选人匹配结果。
- 分项解释、结论、证据片段。
- 原简历预览。
- 字段来源定位和关键词高亮。
- 敏感联系方式不参与推荐摘要和自动匹配判断。

### 3.6 备注、时间线与人工操作追溯

- 候选人备注新增和列表。
- 上传、解析、评分、字段修正、状态变更、批量操作、人才库流转、重复复核等写入时间线。
- 岗位上下文校验，避免跨岗位误操作。

### 3.7 轻量人才库

- 人才库候选人列表。
- 跨岗位搜索。
- 技能、城市、学历、年限筛选。
- 候选人历史岗位。
- 最近匹配结果。
- 标签新增和移除。
- 从候选人详情加入或移出人才库。

### 3.8 岗位管理增强

- 岗位复制、暂停、重新开放、关闭。
- 岗位漏斗统计。
- JD 质量检查。
- `open` 和 `paused` 岗位可编辑。
- `closed` 岗位禁止编辑和重新开放，只能复制后修改。

### 3.9 V2.1 统一上传与重复识别

- 统一上传 API：`POST /api/resumes/upload`。
- 统一上传页：`/resumes/upload`。
- 上传前必须选择归属岗位。
- 岗位内上传继续保留并复用同一处理链路。
- 疑似重复候选人记录：手机号完全匹配、邮箱完全匹配、姓名 + 城市匹配。
- 第一版只提示，不自动合并。

### 3.10 岗位标准版本与重评闭环

- 岗位创建和复制时生成初始标准版本。
- JD、职责、必备条件、加分项、排除条件、评分维度变更时生成新版本。
- 非标准字段变更不生成新版本。
- 匹配结果关联 `job_standard_version_id`。
- 岗位详情展示当前标准版本和版本历史。
- 岗位级批量重新评分接口：`POST /api/jobs/{job_id}/candidates/rematch`。
- 重评结果关联最新岗位标准版本。

### 3.11 推荐摘要第一版

- 推荐摘要接口：`GET /api/jobs/{job_id}/candidates/{candidate_id}/match/recommendation-report`。
- 基于岗位、候选人、最新匹配和分项解释生成 Markdown。
- 候选人详情页可生成、编辑、复制和下载 `.md`。
- 第一版不保存历史，不导出 PDF / Word。

### 3.12 重复候选人人工复核

- 重复检查状态：`pending_review`、`ignored`、`confirmed_duplicate`。
- 候选人详情展示重复风险与复核操作。
- 工作台展示待复核重复风险待办。
- 上传队列展示待复核、已忽略、确认重复统计。
- 复核动作写入候选人时间线。
- 不合并候选人，不修改候选人主档案。

### 3.13 工程与验收

- 后端 pytest 覆盖 V2 主链路、岗位边界、统一上传、重复识别、标准版本、重评和重复复核。
- 后端 ruff 可执行。
- 前端 lint 使用非交互配置。
- 前端生产构建通过。
- API 手动测试脚本包含全量清理工具，默认预览，`--yes` 才执行删除。

## 4. 下一大版本候选池

### 4.1 报告历史保存

当前状态：推荐摘要可生成、编辑、复制、下载，但不入库。

归属：下一大版本候选功能，不再进入 V2.1.x。

建议范围：

- 新增推荐报告历史表。
- 保存 Markdown 草稿。
- 支持历史报告列表。
- 支持打开历史报告继续编辑、复制、下载。
- 保存或更新报告时写入时间线。

### 4.2 文本粘贴录入简历

当前状态：只支持文件上传。

归属：下一大版本候选功能，不再进入 V2.1.x。

建议范围：

- 新增文本录入入口。
- 录入时选择岗位。
- 复用现有解析、评分、重复识别、时间线和上传任务状态链路。
- 明确文本录入生成的 `ResumeFile` 或等价记录如何保存。

### 4.3 ZIP 批量上传

当前状态：前端可多文件选择并逐个上传，但不支持 ZIP 解包。

归属：下一大版本候选功能，不再进入 V2.1.x。

建议范围：

- 上传 ZIP。
- 服务端解包。
- 逐个文件复用现有单文件处理链路。
- 每个文件保留独立任务状态和失败原因。

### 4.4 PDF / Word 推荐报告导出

当前状态：仅支持 Markdown 下载。

归属：下一大版本候选功能，不再进入 V2.1.x。

建议范围：

- 从已保存报告导出 PDF / Word。
- 导出前仍允许人工编辑。
- 导出内容继续遵守敏感信息和风险提示约束。

### 4.5 AI 匹配解释升级

当前状态：分项解释已可用，但主要基于当前匹配结果和候选人字段生成。

归属：下一大版本候选功能，不再进入 V2.1.x。

建议范围：

- 让 AI Provider 输出更严格的 JSON 分项解释。
- 对解释内容做结构化校验和兜底。
- 提升证据片段和维度评分质量。

### 4.6 上传处理异步化

当前状态：同步处理为主，已记录任务状态。

触发条件：真实批量上传等待时间明显影响使用。

归属：下一大版本候选功能，不再进入 V2.1.x。

建议范围：

- 引入后台队列。
- 保留现有任务状态表作为前端查询基础。
- 不改变上传任务和候选人生成的业务语义。

## 5. 明确不进入 V2 的事项

- 自动合并重复候选人。
- 候选人主档案合并。
- 多岗位同时归属同一份简历。
- 完整 CRM 式人才库运营。
- 复杂多角色权限体系。
- 完整多人协作审批流程。
- 面试日程管理。
- 邮件、短信、企业微信、飞书通知触达。
- ATS 系统对接。
- 招聘数据大屏。
- Offer 管理。
- 图片简历 OCR。

其中“候选人主档案合并”“重复候选人合并”“多岗位归属模型”统一归入后续人才库大版本增强，不进入 V2。

## 6. 建议下一阶段

建议下一阶段进入：

```text
V2 Stabilization：V2 稳定化与交付
```

原因：

- V2 已经覆盖可试用招聘工作台主闭环。
- 继续新增小版本会稀释边界，使 V2 变成持续扩展池。
- 当前更重要的是把已做能力稳定、验收、交付和说明清楚。
- 新功能应进入下一大版本统一排序，而不是继续塞进 V2.1.x。

建议验收标准：

- 当前自动化测试稳定通过。
- 当前前端 lint 和生产构建稳定通过。
- V2 验收说明、启动说明、清理脚本和演示路径完整。
- 已知限制在文档中明确列出。
- V2 不再新增业务能力、数据模型或新入口。
- 下一大版本候选池单独排期，不阻塞 V2 交付。
