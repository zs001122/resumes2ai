说明：

- V2.1.1 的第一目标是让 V2.1 已完成能力形成可验收闭环，先补齐岗位编辑、重试重复识别、迁移一致性和自动化检查缺口。
- V2.1.1 的第二目标是完成岗位标准变更后的批量重新评分，使岗位标准版本不只可记录，也可用于历史候选人的重新评估。
- 自动合并重复候选人、完整候选人主档案合并、ZIP 上传、文本粘贴录入、PDF / Word 报告导出继续保留为后续增强；其中候选人主档案合并和重复候选人合并归入 V4 人才库增强，不进入 V2.1.x 开发。

## 2. 复核结论摘要

V2.1 第一版已完成以下能力：

- 统一上传 API 和统一上传页。
- 岗位内上传继续可用，并复用同一上传处理链路。
- 新上传候选人的疑似重复识别与提示。
- 岗位标准版本记录和匹配结果版本追溯字段。
- 推荐摘要 Markdown 生成、编辑、复制和下载。

复核后发现以下缺口需要优先处理：

- 前端缺少岗位编辑入口，HR 无法在界面上触发岗位标准版本变更。
- 单文件重新解析和上传任务重试成功后不会补跑重复识别，可能绕过 V2.1 重复风险提示。
- Alembic 迁移中 `candidate_matches.job_standard_version_id` 只新增了字段，未与 ORM 中的外键定义保持一致。
- 前端 `npm run lint` 仍进入 Next ESLint 初始化交互，无法作为自动化检查项。

## 2.1 当前实现状态

已完成第一版。当前已补齐重新解析和上传任务重试后的重复候选人识别，避免失败恢复成功的简历绕过重复风险提示；重复检查创建已做同一简历、同一候选人、同一匹配对象维度的去重。已修正 Alembic 迁移，使 `candidate_matches.job_standard_version_id` 在空库升级后具备到 `job_standard_versions.id` 的外键约束。

前端已新增岗位编辑页 `/jobs/:jobId/edit`，岗位详情页对开放和暂停岗位展示编辑入口，关闭岗位不可直接编辑。岗位标准版本提示已补充批量重新评分入口；候选人列表的批量重新评分也改为使用新的重评接口。后端已新增岗位级批量重新评分接口 `/api/jobs/{job_id}/candidates/rematch`，支持全量或指定候选人重评，重评结果关联最新岗位标准版本，并对不属于当前岗位的候选人返回部分失败结果。

自动化验证已补齐前端 ESLint flat config，`npm run lint` 可非交互执行。当前已通过后端测试、后端 ruff、前端 lint、前端生产构建和临时库 Alembic 升级外键检查。

## 3. 阶段目标

V2.1.1 目标是完成“岗位标准变更 -> 版本记录 -> 历史候选人重评 -> 匹配结果追溯”的闭环。

重点解决：

- HR 可以在前端编辑开放或暂停岗位的 JD 和筛选标准。
- 关闭岗位不能直接编辑，只能复制后修改。
- 岗位标准字段变更后自动生成新版本，并在岗位详情页提示建议重新评分。
- HR 可以对岗位下已有候选人按最新标准批量重新评分。
- 新评分结果必须关联最新岗位标准版本。
- 上传失败后的重试或重新解析仍必须执行重复候选人识别。
- 数据库迁移与 ORM 模型保持一致。
- 自动化验收命令可以覆盖后端测试、后端 lint 和前端构建；前端 lint 如要保留脚本，必须可非交互执行。

## 4. Phase 21：V2.1 验收缺口修复

### 4.1 后端任务

- 抽取或复用统一的“解析成功后处理”逻辑，避免首次上传、重新解析和上传任务重试出现行为分叉。
- 在 `POST /api/resume-files/{resume_file_id}/parse` 成功解析后执行重复识别。
- 在 `POST /api/jobs/{job_id}/upload-tasks/{task_id}/retry` 解析失败恢复成功后执行重复识别。
- 重试或重新解析产生重复风险时，同步更新 `UploadProcessingTask.duplicate_count` 和 `has_duplicate_risk`。
- 避免同一个 `resume_file_id` 重复生成完全相同的 `pending_review` 重复检查记录。
- 修正或补充 Alembic 迁移，使 `candidate_matches.job_standard_version_id` 与 `job_standard_versions.id` 的关系和 ORM 保持一致。

### 4.2 前端任务

- 增加可自动化的前端 lint 配置，或调整 `npm run lint` 为明确可执行的检查命令。
- 保持当前 `npm run build` 验证不回退。

### 4.3 验收标准

- 首次上传、重新解析、任务重试三条路径成功生成候选人后，重复识别行为一致。
- 同手机号或同邮箱候选人通过重试恢复成功时，上传任务能显示重复风险。
- 重复检查不会因为多次重试产生重复噪音记录。
- Alembic 从空库升级到 head 成功，迁移后的表结构和 ORM 的关键约束一致。
- 自动化检查命令不会进入交互式初始化。

## 5. Phase 22：岗位编辑与标准版本前端闭环

### 5.1 后端任务

- 继续保留当前规则：`open` 和 `paused` 岗位允许编辑，`closed` 岗位禁止编辑。
- 岗位标准字段变化时继续生成新的 `job_standard_versions` 记录。
- 非标准字段变化不生成标准版本。
- 岗位标准版本列表接口继续按版本号倒序返回。

### 5.2 前端任务

- 新增岗位编辑页或岗位详情内编辑面板。
- 岗位详情页提供“编辑岗位”入口，仅对 `open` 和 `paused` 岗位显示或启用。
- 关闭岗位隐藏或禁用编辑入口，并提示“请复制岗位后修改”。
- 编辑页支持修改岗位基础字段、JD、职责、必备条件、加分项、排除条件和评分维度。
- 编辑标准字段时提示“标准变更会影响历史评分一致性，保存后建议重新评分”。
- 保存后返回岗位详情，并刷新当前标准版本和版本历史。

### 5.3 验收标准

- HR 可以从岗位详情页进入编辑页。
- 开放岗位和暂停岗位可以编辑。
- 关闭岗位不能编辑。
- 修改 JD、必备条件、加分项、排除条件或评分维度后会生成新标准版本。
- 只修改部门、地点、薪资等非标准字段时不生成新标准版本。
- 前端保存失败时展示后端错误信息。

## 6. Phase 23：岗位标准变更后批量重新评分

### 6.1 后端任务

- 新增岗位级批量重新评分接口，建议路径：

```text
POST /api/jobs/{job_id}/candidates/rematch
```

- 支持对岗位下全部候选人按最新岗位标准重新生成匹配结果。
- 支持可选 `candidate_ids`，用于只重评选中的候选人。
- 新生成的 `CandidateMatch` 必须关联当前最新 `job_standard_version_id`。
- 每个成功重评候选人写入时间线。
- 部分候选人重评失败时返回部分成功和失败原因，不阻断其他候选人。
- 如果岗位没有标准版本，返回明确错误或按当前岗位标准补建初始版本后继续。

### 6.2 前端任务

- 岗位详情页在标准版本数大于 1 时展示“建议重新评分”提示。
- 提供“批量重新评分”按钮。
- 候选人列表保留现有批量重新评分能力，并确认其使用最新标准版本。
- 重评过程中展示 loading 状态。
- 重评完成后刷新候选人列表、岗位详情统计或当前候选人匹配结果。
- 部分失败时展示失败数量和原因摘要。

### 6.3 验收标准

- 标准版本变更后，HR 可以一键对岗位下历史候选人重新评分。
- 重评后的最新匹配结果关联最新标准版本。
- 候选人详情展示的最新匹配结果来自最新重评。
- 重评操作写入候选人时间线。
- 单个候选人失败不会导致整批任务全部失败。

## 7. Phase 24：验收测试与文档更新

### 7.1 后端测试

- 覆盖岗位编辑生成新标准版本。
- 覆盖关闭岗位禁止编辑和禁止重新开放。
- 覆盖非标准字段编辑不生成新标准版本。
- 覆盖批量重新评分后 `job_standard_version_id` 更新为最新版本。
- 覆盖重新解析和上传任务重试后的重复识别。
- 覆盖重复检查去重，避免同一简历多次重试生成重复记录。

### 7.2 前端验证

- `npm run lint` 若保留，必须非交互执行并通过。
- 手动确认岗位编辑页、关闭岗位禁用编辑、批量重新评分入口和失败提示。

### 7.3 文档更新

- 更新 `V2_1_TASK_BREAKDOWN.md` 中的 V2.1.1 状态引用。

## 8. 推荐实施顺序

建议顺序：

```text
Phase 21：V2.1 验收缺口修复
  -> Phase 22：岗位编辑与标准版本前端闭环
  -> Phase 23：岗位标准变更后批量重新评分
  -> Phase 24：验收测试与文档更新
```

原因：

- 先修复已发现缺口，避免后续开发建立在不完整链路上。
- 再补岗位编辑前端闭环，让标准版本能被真实 HR 操作触发。
- 最后实现批量重新评分，把版本追溯转化为可用的业务闭环。

## 9. V2.1.1 不做事项

- 自动合并重复候选人。
- 候选人主档案合并。
- 多岗位同时归属同一份简历。
- ZIP 批量上传。
- 文本粘贴录入。
- PDF / Word 推荐报告导出。
- 多角色权限。
- ATS 对接。
- 通知触达能力。

## 10. 后续增强候选
